# Client Interview

Скилл маршрутизирует работу по интервью с клиентом. Источник правды - `project/docs/interviews/playbook-source.md`.

## Иерархия

```
Проект клиента
└── Серия бесед
    └── Беседа = Темы + Модули + Закрытие + Постобработка
```

## Когда подключается

- Подготовка беседы: выбрать Темы, Модули и глубину.
- Закрытие беседы: проверить достаточность данных и договориться о следующем шаге.
- Постобработка: оформить summary в `project/docs/interviews/<YYYY-MM-DD>-<client-slug>-conv<N>-summary.md`.
- Обновление методики: сначала менять `playbook-source.md`, затем синхронизировать этот скилл.

## Роли

- PM: согласует состав беседы и ревьюит summary.
- Ассистент PM: помогает с подготовкой, ревью и синхронизацией методики.
- Аналитик: участвует в беседе и оформляет summary; после серии бесед запускает цикл методика -> ТЗ.
- Клиент: отвечает бизнес-языком.

## Жесткие правила

1. С клиентом говорить только бизнес-языком.
2. As-is перед to-be.
3. Боль важнее желаний.
4. Границы scope фиксировать явно.
5. Не угадывать: «обычно», «много», «часто» раскладывать в факты и числа.
6. Один вопрос за раз.
7. Реплики-связки только содержательные.
8. Каждую боль раскручивать до конкретной истории, цифр и последствий.
9. Состав беседы фиксируется на подготовке и в ходе беседы не расширяется.
10. Обязательный вопрос Темы или Модуля можно переформулировать, но нельзя пропустить без причины.
11. У интервью две цели: сформулировать задачу и собрать достаточно данных по затронутым бизнес-блокам.
12. Объем беседы регулируется составом, не сокращением ядра вопросов.
13. Артефакт каждой беседы - файл summary, не сообщение в чате.
14. После серии бесед итоговая формулировка идет в стандартный цикл Аналитика.

## Что делать при вызове

1. Прочитать `project/docs/interviews/playbook-source.md`, если он еще не прочитан в этой сессии.
2. Показать короткую карту: Темы T1-T6, служебные фазы, Модули M1-M6/M5.
3. Уточнить, какая фаза или какая беседа интересна.
4. Углубиться в соответствующий раздел playbook.

## Чего не делать

- Не вести беседу за Аналитика.
- Не писать ТЗ из summary.
- Не дублировать весь playbook внутри скилла.
